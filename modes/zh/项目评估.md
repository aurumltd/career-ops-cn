# 模式：项目评估 — 作品集项目优先级与优化建议

## 当用户不知道应该做什么项目来增强简历时使用此模式

## 评估框架

### 第一步：诊断当前作品集质量

| 等级 | 描述 | 行动建议 |
|------|------|----------|
| S 级 | 2-3 个高质量项目，有数据、有链接、有文章 | 保持更新，根据目标职位微调描述 |
| A 级 | 有项目，但描述太泛、没有数据 | 补充量化结果，重写描述 |
| B 级 | 只有学校作业 / 课程项目 | 需要 1 个能展示真实问题解决能力的项目 |
| C 级 | 完全没有项目 | 从一个 2 周能完成的最小可行项目开始 |

### 第二步：根据目标职位匹配项目优先级

| 职位类型 | 最有说服力的项目类型 |
|----------|---------------------|
| **AI / LLM 工程师** | 真实用户使用的 Agent、RAG 系统、微调案例 |
| **前端工程师** | 复杂交互 Demo、性能优化、开源贡献 |
| **后端工程师** | 分布式系统、数据库优化、高并发处理 |
| **数据工程师** | 完整 ETL 流水线、数据治理案例 |
| **产品经理** | 用户研究报告、产品路线图、A/B 测试案例 |
| **设计师** | 完整设计流程案例、设计系统、用户测试 |

### 第三步：项目 ROI 评估

对每个候选项目评估：

| 维度 | 评分 1-5 | 权重 |
|------|----------|------|
| 完成时间 | 越短越好 | 30% |
| 差异化程度 | 多少人有类似项目？ | 30% |
| 与目标职位相关性 | 直接命中 JD 要求吗？ | 25% |
| 展示价值 | 面试时有东西可讲吗？ | 15% |

## 项目优化模板

### 好的项目描述 = 情境 + 行动 + 数据

❌ 不好的：
> "构建了一个基于 LLM 的聊天机器人"

✅ 好的：
> "为解决客服响应慢问题，设计并实现了基于 GPT-4 + RAG 的聊天机器人，处理 1000+ 用户查询，准确率 87%，平均响应时间从 2 小时降到 30 秒。"

### 每个项目必备的 5 个要素：

1. **一句话摘要**：这个项目解决了什么真实问题？
2. **技术栈 / 方法论**：你用了什么工具？
3. **你的具体贡献**：不是"我们"，是"我"
4. **量化结果**：数字、百分比、对比
5. **在线链接**：GitHub / Demo / 文章

## 💡 通用优化建议

### 你的现有项目需要补充的：
1. **项目 A**：缺少量化结果，补充用户数 / 性能指标
2. **项目 B**：描述太技术化，需要加 1 句业务价值
3. **项目 C**：没有在线链接，立即部署到 Vercel / GitHub Pages

### 不要做的项目：
- ❌ Todo List / 博客系统（100 万候选人都有）
- ❌ 跟着教程抄的项目（面试官一眼就能看出来）
- ❌ 需要 3 个月以上的大项目（时间成本太高）
